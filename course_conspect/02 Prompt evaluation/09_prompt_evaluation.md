# Prompt evaluation

## Урок 9. Prompt evaluation

Ссылка: https://academy.claude.com/courses/building-with-the-claude-api/prompt-evaluation

Теория, кода нет.

### Главное

- **Prompt engineering** — как писать prompt: примеры (multishot), структура через XML-теги и другие приёмы.
- **Prompt evaluation** — как измерить, насколько хорошо prompt работает: автоматические тесты.

Что даёт evaluation:
- сравнить ответы с ожидаемыми;
- сравнить разные версии одного prompt;
- найти ошибки в ответах.

### Три пути после написания prompt

1. Проверить один раз и решить, что хватит. Высокий риск, что prompt сломается в production на неожиданном вводе.
2. Проверить несколько раз и поправить пару крайних случаев. Лучше, но пользователи всё равно присылают то, что не предусмотрели.
3. Прогнать prompt через evaluation pipeline, получить оценку и улучшать prompt по метрикам. Дольше и дороже, но надёжнее.

Пути 1 и 2 — частая ловушка: разработчики недооценивают, сколько необычных вводов будет у реальных пользователей.

### Подход «сначала evaluation»

Evaluation pipeline даёт объективные метрики на большом наборе тестов. Это позволяет:
- найти слабые места до production;
- сравнивать версии prompt по цифрам;
- улучшать prompt по измеримому результату;
- делать надёжные AI-приложения.

Цель — найти проблемы при разработке, а не после жалоб пользователей.

# Prompt engineering techniques

## Урок 18. Structure with XML tags

Ссылка: https://academy.claude.com/courses/building-with-the-claude-api/structure-with-xml-tags

### Главное

Когда в prompt много текста, Claude может не понять, какие части связаны
между собой и что каждая часть значит. XML-теги отделяют части prompt друг
от друга. Особенно полезно, когда в prompt подставляется много данных.

### Зачем нужна структура

Пример: в prompt подставлены 20 страниц записей о продажах. Без границ
Claude сложно отличить инструкции от данных, которые нужно
проанализировать.

Решение — обернуть данные в теги:

```
<sales_records>
...записи о продажах...
</sales_records>
```

### Пример: код и документация

Prompt: найти ошибку в коде с помощью документации. Если код и
документация идут сплошным текстом, непонятно, где что. С тегами
`<my_code>` и `<docs>` граница видна сразу.

### Свои названия тегов

Специальных официальных тегов нет, название придумываем сами. Чем точнее
название, тем лучше Claude понимает, что в этой части:
- `<sales_records>` лучше, чем `<data>`;
- `<athlete_information>` — сразу видно, что это данные спортсмена;
- `<my_code>` и `<docs>` — разные виды содержимого.

### Когда использовать

- в prompt много контекста или данных;
- смешаны разные виды содержимого: код, документация, данные;
- нужно чётко показать границы частей;
- сложный prompt, в который подставляется несколько переменных.

Даже в коротком prompt теги помогают: структура становится понятнее.

### Пример: план питания

```
<athlete_information>
- Height: 6'2"
- Weight: 180 lbs
- Goal: Build muscle
- Dietary restrictions: Vegetarian
</athlete_information>

Generate a meal plan based on the athlete information above.
```

Так видно, что рост, вес, цель и ограничения — данные одного спортсмена,
и учитывать их нужно вместе.

На простых prompt большого роста балла может не быть. Чем сложнее prompt и
чем больше в нём разных данных, тем больше пользы от тегов.
